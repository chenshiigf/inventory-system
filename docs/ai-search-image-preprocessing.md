# AI 找货上线准备第1步：浏览器图片预处理

2026-10-14。本阶段只修改 `/ai-search` 的图片输入链路，不调整模型、图库、向量、业务数据库、鉴权或生产环境。

## 行为和限制

- 原始 File 和原图预览留在浏览器会话中，选择照片不上传；超过10MiB不再直接拒绝。
- 点击搜索时才生成独立 JPEG。默认长边1600，不放大小图，最多3,000,000像素、2MiB；编码质量从0.9开始，超限时有限次降低质量/尺寸，失败不会发起搜索。
- 框选坐标对应 EXIF 纠正后的完整原图。直接用原始 ImageBitmap 的选区绘制到输出 Canvas，先裁剪再缩小；不从缩小后的整图或上次查询图片裁剪。
- JPEG 已含框内像素，搜索请求不再提交 `crop`，避免后端重复裁剪。原坐标、图片版本、裁剪版本仍保留用于会话失效和反馈校验；后端响应 `crop=null` 按实际记录保存，不伪造原图坐标。
- JPG、PNG、WEBP；透明像素变白，EXIF方向只纠正一次。原图仍保留40,000,000像素上限。ImageBitmap和Canvas在成功、失败、取消时释放。
- 保持 `source=production-catalog`、`top_k=5`、单次请求、人工确认、只读详情及复制货号。选择照片/搜索期间禁止重复操作，改变原图或选区后旧结果失效。
- 后端现有10MiB、40MP、静态格式检查完全不变；仍执行原有1024长边预处理。低层 `searchVisual` 的可选crop接口继续保留，其他工具不受影响。

1600是降低服务器解码负担的初始候选；2048仅用于离线对比，方形2048也受3MP限制。未获真实模型准确率验证，不能称为最优参数。

## 零费用验证

全部真实浏览器测试使用独立Chrome会话。外部网络被拦截；页面搜索/反馈/详情用Mock，独立Next测试服务的后端指向不可用回环端口9。没有连接百炼、写入查询反馈或改变业务数据。

- 原有320×200小图可处理，不放大；JPEG重新编码可能使极小文件略增，本例1824→2221字节，不能宣称每张图片字节都会降低。
- 真实Canvas验证EXIF1～8，包括镜像/转置：原生预览尺寸、框内像素颜色、输出方向一致。PNG/WebP透明图输出白底。
- Mock UI整图、反向框选、重新框选、Top5、确认、复制货号和只读详情通过。每次搜索只有一个Mock POST，均未携带crop。重新框选保留4000×3000原图，清空旧确认。
- 注入Canvas编码失败：显示明确处理错误，新增搜索请求为0。解码/编码失败、尺寸异常、取消、过期响应由离线回归覆盖。
- 将Mock截获上传文件交给原后端 `prepare_image(data, None)` 离线验证：全部符合大小/像素限制。现场选区到Provider前仍为826×756，仅重新编码，没有二次裁剪；已目视检查杯身、把手、纹理保持完整。
- 前端全部48项Node测试通过，完整TypeScript检查0诊断，专项ESLint通过。没有绕过类型检查。

测试照片、上传输出与截图仅在Git忽略目录 `output/playwright/ai-image-preprocess/`；不纳入提交或公开artifact。

## 复验

在 `web` 目录执行：

```powershell
node --test tests/*.test.mjs
node node_modules/typescript/bin/tsc --noEmit --incremental false
node tests/ai-search-image.browser.mjs
```

最后一个命令启动临时回环HTTP服务，打开打印的地址即运行真实浏览器Canvas测试；Ctrl+C关闭。可加 `--photo <本地现场JPEG路径>` 进行私有离线1600/2048对比；只读取该图片，无后端接口或模型连接。正式网页点击搜索仍会产生真实API调用，需另行授权，不能作为本阶段离线验收方式。

## 仍需人工验收的边界

- 本阶段已验证图片处理与交互，未测试压缩后真实模型Top1/Top5准确率；参数是否影响困难样本需另行授权。
- HEIC不在现有支持范围，需手机导出为JPG。原图解码仍消耗客户端内存；超过40MP继续拒绝，旧浏览器能力不足时明确失败。
- 本轮未重新测量Linux/生产服务器实际内存峰值，也未进行部署。本阶段降低了服务器收到的字节和像素，不能据此宣称生产资源验收完成。

完成第1步后暂停，不自动推进后续上线步骤。
