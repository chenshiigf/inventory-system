# Phase 1.8 现场照片评测

本阶段复用现有视觉搜索，不构建商品向量、不连接生产服务器、不操作库存。
第一步是离线链路预检；真实查询等待现场照片及调用对象/数量/预算确认，准确率验收另待人工正确答案。

## 离线链路预检

在项目根目录运行：

```powershell
& api/.venv/Scripts/python.exe api/scripts/check_field_search.py --load-local-env
```

脚本通过 SQLite 只读连接和在线备份生成独立索引副本，生产图库保持只读。
使用合成灰色图片及注入的已知向量，检查完整图库模型配置、商品 ID 集合、主图 SHA256、向量缓存、Top 5 排序、镜像详情及整图/手动裁剪路径。
它没有真实 Provider，不能调用百炼。注入向量仅用于检查链路，不能证明模型识别准确。
原索引、历史查询/反馈、开发数据库、Phase 1.5 索引及图库数据库在执行前后校验文件哈希。
每次报告和副本保存于独立的 `api/data/visual-search/field-evaluation/preflight/offline-*/`，不覆盖此前记录。

现有 API Mock 测试另外覆盖管理员鉴权、生产来源选择、图片读取、镜像详情和同名开发 ID 隔离。
生产查询使用 `/api/visual-search/search?source=production-catalog`；裁剪参数为现有比例坐标 `[x, y, width, height]`，相对 EXIF 校正后的原图。
页面默认选择“生产商品图库”，详情和主图跟随查询结果的来源，不能切换到开发商品详情。

## 测试资料

所有真实资料放在 Git 忽略的 `api/data/visual-search/field-evaluation/`：

```text
originals/       原始现场照片，保留原件
labels.json     人工标注；未提供答案的对象保持未标注
runs/           每次查询的独立结果、实际区域、用量与统计
preflight/      离线 Mock 预检副本和报告，不纳入真实评测
```

`api/.gitignore` 已忽略整个 `data/visual-search/`，不将照片、标签、商品资料或密钥提交 Git。
目前 `labels.json` 是空测试集，不填虚构样本。
每个对象需要保存：`image_id`、`object_id`、相对原图路径 `image`、
`source_id=aliyun-inventory-production`、人工确认的 `product_id`、实际 `product_code`、
`multi_product`、`needs_crop`、比例坐标 `crop` 或 null、`category`、`environment` 和 `notes`。
未知正确商品 ID 保持 null；推荐第一名不能成为人工答案。
多商品照片拆分为独立对象，保留同一原图关系，每次手动裁剪分别记录。

真实执行前核对照片不是图库原始主图或其简单转换。盲测先查询，不预先要求正确 ID/货号；查询后由用户人工核对，与镜像校验一致再记录正式标签。
即使文件哈希不同也不能自动证明是现场照片，来源仍需人工确认。
优先单体白房屋、组合白房屋，以及相似外观、不同角度、杂乱背景和多商品照片。

## 真实查询边界与报告

本轮最多 10 个评测对象，且保守限制总真实请求不超过 10 次。
整图和裁剪比较各消耗一次请求，失败请求也计数；串行执行、关闭自动重试。
执行前列出具体对象、预计请求数及预算，等待用户确认。失败或用量缺失先停止，不自动重复付费。
每次保存原图/区域、查询 ID、来源、模型/版本、索引身份、Top 5 完整候选详情及相似度、实际 Token、费用估算和耗时。
保留成功记录，重复评测使用新 run，不能覆盖标签或人工反馈。

精确排名仅按人工确认的商品 ID 计算。另列正确商品主图 SHA256 对应的共图候选及其排名，
不能把同图的其他商品计为精确 ID 命中。未标注或身份无法判定的对象不进入精确命中率分母，并单列数量。
报告 Top 1/3/5、未进 Top 5、共图歧义、平均/P95 耗时、平均费用以及品类/环境分组结果；
P95 使用 nearest-rank（排序后第 ceil(0.95*n) 项），说明小样本限制。
相似度是向量分数，不是正确概率。

现有 `visual_search.py evaluate` 只提供基础统计，会截取 `max-items` 且缺少上述完整报告和阶段调用保护，
不直接用它宣称 Phase 1.8 验收完成。收到真实资料后补齐本轮受控执行及报告，再决定是否需要模型或主图优化。
本轮结果出来前，不给出准确率、错误原因结论或 50～100 张扩展建议。

## 盲测安排

用户确认本轮最多 10 次真实请求，预算上限 1 元，先看候选再标注正确商品。
查询仅传图片区域，不附加商品 ID、货号、对象描述或正确答案。
多商品照片先生成独立 `plans/<timestamp>/plan.json` 及 `review.html` 展示建议框，等待用户确认才执行。
所有原始照片、计划和裁剪预览保存在忽略目录；预览只绘制 HTML 覆盖框，不改变原图。
`labels.json` 保持独立，未经人工确认不写入正确 ID；无法判定标记待核实并排除准确率分母。
预算按 API 返回用量估算并在下一次调用前预留费用，不是百炼账单硬限额；返回用量不可靠时停止，失败请求也计入 10 次限制，不自动重试。
