优先采集未搜索过的新实物/新现场图。历史照片或同一商品的新角度可列为复测/配对，必须标明曾测试关联，不混称全新泛化样本。E 共图保持每个生产 ID 独立，不合并库存商品。

## 标签、裁剪与模型输入隔离

每个对象记录 object_id、来源 source_id、原图引用/哈希、裁剪坐标/确认人/时间、实际输入哈希、商品类别、主分类/困难标签、是否多商品同框、共图 SHA 组、混款关系、派生图片来源、历史关联和备注。

正确标签单独保存：status（present/absent/pending/ambiguous）、精确生产 ID / 货号、人工确认人/时间、独立证据、冻结哈希。absent 的 ID / 货号为空；pending 不强迫猜测。照片中的手写字、吊牌或模型分数不能代替正确商品标签。

- strict：在任何搜索前完成独立标签和裁剪确认。结果失败也保留原标签，不能按 Top1 改答案。
- exploratory：可以获准后先看候选，再由人查实；查询后确认记录为 post-search 核对，仅作为探索案例，不转入本轮正式准确率。
- D：查询前先确认图库不存在。它没有正确生产 ID，单列探索/开放集指标，不进入普通 strict 分母。
- E：唯一商品身份未能确定时标 ambiguous；已知某 SHA 组也不能把组内所有商品都当精确匹配成功。真正升级 strict 必须发生在查询前。

先冻结严格标签文件，再生成 answer-free query-objects：仅对象编号、图片引用、裁剪区域与来源。模型请求只传裁剪图片字节及既定模型/维度参数；ID、货号、标签、类别、备注、文件名和名额说明不发给模型。

裁剪须保留完整主体且尽量排除其他商品和无关文字。遮挡样本保留现场真实遮挡并记录可见比例/原因，不自动修复或生成图片。组合对象不能擅自拆分生产商品身份。现有框有问题时只报告，调整后另存修订并重新确认。

## 评测执行和成本草案（尚未授权）

先完成 30 个名额的采集和人工确认，不必等待 30 张不同照片。建议拆成 3 批，每批 10 个：每批 A 至少 3、B/C/D/E 至少 1，余下 3 个按名额补足；最后各类满足 10/5/5/5/5。具体对象和模式逐批冻结，取得用户明确对象数、裁剪和预算许可；第一批正常不代表自动授权后两批。

每对象一次，整图/裁剪、原图/微信压缩的额外对照与失败重测必须提前计入请求数。串行，间隔至少 1 秒，关闭自动重试；用量缺失、响应结构/维度异常、费用异常、图片或来源变化立即停止。请求前保存意图检查点，之后保留实际账本与已完成记录；不能自动重试可能已收费的未确认请求。

索引使用既有本地只读源的独立 SQLite 在线快照，2414 商品 / 2380 内容向量完整性校验通过后方可查询。查询/费用写入独立新 run，不改原索引、生产镜像、开发数据库、Round1 或 Round2。

北京官方原价于 2026-10-12 核对：图片 1.8 元/百万 Token，文本 0.7 元/百万 Token，[官方价格](https://help.aliyun.com/zh/model-studio/qwen3-vl-embedding)。历史 13 次查询总估算费用 0.0130072 元，平均约 0.00100055 元/次；按历史最高单次 0.001801 元估算，30 次约 0.0300～0.0540 元。建议按约 0.03～0.06 元规划，困难图片用量可能不同，不保证未来实际费用。

建议新阶段总额仍使用 1 元本地累计估算停止阈值，跨三个批次累计且失败计入，逐批请求许可单独确认；当前该预算未获本阶段执行授权。每次预留下一次保守费用，按实际返回 Token 计费。此为本地保护，不是百炼账户账单硬上限；未能核对价格/用量或保护无法可靠执行时先停，不声称存在硬限额。

## 指标、错误归类和新报告

报告保存每个对象原图/确认裁剪、Top5 商品主图、真实来源 ID、货号、规格、相似度、正确排名（含未进 Top5）、API 请求 ID、实际 Token / 费用、失败账本、分段耗时、首次/后续请求、CLI 启动口径。

困难分类报告分别列实际样本数、已预标注 strict 分母、Top1/3/5、待核实与 exploratory 数；同时按品类和拍摄困难分组。无样本/无有效分母时填“尚未评测”，不填 0% 或 100%。横跨多个困难标签的分组可以重叠，但累计分母按唯一对象计数。

共图指标单列“精确 ID 排名”和“正确 SHA 视觉组是否进入 TopK”。视觉组命中不能代替精确商品 ID 命中；混款对象的人工可辨性与事前身份依据另列。检索分数和第一、二候选差值仅用于分析，不当成正确概率或事后调阈值。

D 单列：非空候选返回率、Top1 相似度分布、人工是否误选图库商品、正确拒绝/复核/不确定计数。现有系统主要返回候选，没有已验收自动拒绝策略；仅返回 Top5 不等于系统已经确认匹配。没有明确决策时拒绝率为 N/A / undecided，不能把全部返回候选直接算业务错误接受，也不能把未决算拒绝成功。不通过新阈值掩盖图库外误推荐。

错误类型至少包含：近似款混淆、颜色混淆、尺寸视觉不可辨、主体太小/背景干扰、遮挡、角度、低光、压缩损失、参考主图不足、共图身份不可辨、混款关系不明、图库外误选择，以及非识别错误的 API/数据/计费失败。每例给出真实裁剪、候选、人工证据、可确认原因与不确定原因；不能把所有错误都归因模型。

错误分析先记录已有结果，再建议补拍、人工裁剪或资料核对。任何额外模型对照都是另一次需要授权的付费请求；不未经测量更换模型、引入重排序或调整匹配权重。

## 约 4 秒是否适合实际出库

目前能支持低频单款、由人确认的找货辅助；批量、多款连续出库体验尚不足，且没有真实员工/手机链路验收。13 个小样本命中不能证明自动出库可用。本阶段只模拟认货与选择，不创建正式出库记录或扣库存。

Round2 是同进程 FastAPI ASGI TestClient + 真实百炼调用，没有测浏览器、手机上传和 TCP 链路。4 个请求的平均 4.156 秒、P50 4.102 秒、P95 4.344 秒；热请求平均 4.093 秒、P95 4.124 秒；首次 4.344 秒，百炼平均 0.548 秒。小样本 P95 接近观测最大值，不能当生产尾延迟承诺。CLI 首条计时语句到 ready 为 1.663 秒，不含操作系统启动 Python 的未测部分；准备/完整索引预检另计。

| 热请求分段 | 平均秒 | 含义 |
| --- | ---: | --- |
| 读取向量 SQLite | 0.038 | 当前不是主要瓶颈 |
| 批量商品元数据读取 | 0.021 | 已有 bulk 读取，不再提重复消除 N+1 |
| 查询前图片哈希/向量校验 | 1.527 | 全图库检查 |
| 查询向量生成段 | 0.974 | 含评测保护/账本/向量保存；真实 API 热请求均值约 0.498 秒 |
| API 后图库复核 | 1.472 | 第二遍全图库检查 |
| NumPy 相似度 | 0.029 | 已批量计算，换检索库收益有限 |
| 预处理/保存/响应等 | 约 0.019 | 请求内分段，其余上传/鉴权/框架开销另计 |

两遍图库校验合计约 2.999 秒，占热端到端约 73%。向量段减实际 API 约 0.476 秒是测得的包装剩余开销，包含保护哈希、账本与向量保存，未单独测量，不能全部归给鉴权或某一个函数。

若每款串行 4.1 秒，5 款仅搜索等待约 20.5 秒，10 款约 41 秒，尚未包括拍照、框选与人工核对。这是线性外推，不是已完成多款现场吞吐测试。

## 仅提出、不实施的优化顺序

1. 先分别量出评测保护、正常常驻请求、浏览器/手机上传耗时。复用已保存的真实查询向量对比本地路径，无需再次付费来检查排序；不把离线向量测量当真实端到端测试。
2. 若进入实现，优先考虑发布时完整哈希验证 + 来源/模型/预处理/索引更新版本关联的常驻内存快照；请求检查发布代次、仅复核必要候选，更新原子切换且立即失效缓存。必须先有可验证的不可变镜像发布/变更协议，手工修改也能触发失效；不能仅靠 mtime 降低正确性保障。如果协议无法保证，保留现有全量校验。
3. 缓存可持有 2380 个 float32×2560 向量约 23.24 MiB（或 2414 个约 23.57 MiB），另加 metadata/ID 映射/框架内存。共图复用向量仍返回独立 ID；不是合并商品。实际进程/峰值内存需再测，不将矩阵大小当进程总内存。
4. 常驻服务复用已载入索引/元数据，避免每个对象新开 Python；数据库连接复用、向量矩阵缓存属次级优化，现有这两项读取/计算总计仅约 0.07 秒，不预期它们独自解决 3 秒瓶颈。
5. 若需业务体验优化，考虑清楚的处理状态、逐对象结果显示、无需重新上传的重新框选和人工候选核对；这些仅为后续建议，本阶段不改界面、不新增自动检测或批量付费调用，不开发出库动作。

争取热端到端 3 秒以内、P95 不超过 5 秒为待确认的体验目标，不是现阶段保证。可用性模拟另记员工总操作时间、框选次数、误选/取消/重新拍照次数、手机等待体验。没有相同真实请求口径的验证前，不宣称优化已经生效。
