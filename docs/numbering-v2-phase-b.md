## 新品与旧号检索

- 创建服务取一个 UTC 建档时间，转换为北京时间确定月份；建档时间和发号使用同一个时间值。API 与正式 Excel 导入继续共用该服务。
- `YYMM + 至少两位序号`，每月独立，超过 99 自动扩位。现有 `BEGIN IMMEDIATE`、单事务 UPSERT 和唯一索引共同防止并发重复；外层回滚同时回滚计数器。
- 避让数据库当前已存在的月份格式编号，包含停用品；不为已退役的旧号预留新流水。不因类别、仓库或库存变动重新发号。
- 旧自家编号精确搜索通过持久映射返回当前商品，原供应商货号仍使用原字段。若某旧号也是另一商品的当前号，搜索同时返回两款，按商品 ID 和照片核对；不暗中覆盖其中一条身份。
- 旧回填命令停止在导入默认业务数据库之前；升级后的库也拒绝旧三段式回填。

## 离线程序

入口为 `python -B api/scripts/numbering_v2.py`。不导入应用启动代码、不管理服务、不创建调用锁、不初始化向量或预算，不调用模型。

1. **plan（dry-run）**：指定业务库、独立且逐字节相同的业务/镜像备份、visual 根、catalog 根、namespace、index_key 和外部报告目录。先持有两个已有调用锁，拒绝启用的 AI 标记、运行中的索引任务、日志文件、WAL、链接、同库/跨设备目标、错误版本和来源；固化完整映射、每商品/仓库库存、全部非编号字段及其他表/结构摘要、AI 保护文件 SHA256。报告保存含完整原值映射的 `report.json` 和校验清单，不生成额外的表格格式。
2. **execute**：要求完整批准 SHA256 和 `--confirm-writers-stopped`。重新生成并逐项比较计划，先把计划持久化到独立外部输出目录，再使用唯一临时编号解决目标号与旧号重叠。
3. **verify**：只读核对持久登记、完整映射、全部业务不变量、镜像不变量、计数器、备份和 AI 保护文件。提交后外部回执失败返回 `committed_report_failed`（CLI 退出码 3），应执行 verify；任何重复 execute 都被持久登记拒绝。
4. **restore**：同样要求批准 SHA256、停止写入确认和独立输出目录。先验证切换后状态完全不变；发现新商品、库存/流水/备注/时间变化、月份计数变化或 AI 保护文件变化均拒绝。仅用同一跨库事务逆向恢复编号及镜像版本，不把旧数据库文件覆盖到当前数据上。恢复生成新 revision，旧 AI 会话不会重新变得有效。完成后 verify 返回 `restored_verified`，重复恢复或换号均拒绝。

所有报告必须在仓库和业务/AI 数据目录之外。路径不允许符号链接、junction/reparse point、硬链接或 `..`。原始备份、正式恢复授权和服务器操作不包含在此 CLI 的授权内。

### 一致性是独立门槛

plan 必须二选一：

- `--offline-test`：仅供独立测试副本；所有计划/执行/核验结果带 `scope=offline-test`，**不证明跨库一致性、不等于允许正式换号**。这允许 B 用合成数据测试程序，不将 A3 历史备份的 PENDING 改成通过。
- `--consistency-evidence <path>`：输入人工审查过的 JSON；格式 `numbering-v2-consistency-v1`，包含 `reviewed: true`、非空 `backup_set`、`method`，以及 `sha256` 中 business/catalog/index/budget 四个当前文件的精确哈希。工具验证绑定和内容未漂移，但不能替人确认生成方法、授权或证据真实性。迁移前原备份、迁移后待切换文件及新备份的对应关系须在 C 中记录。

### 跨库原子性与故障出口

业务文件作主库、镜像通过 ATTACH 接入，二者须在同一本地文件系统、使用 DELETE rollback journal，连接设置 `synchronous=FULL` 后开启 `BEGIN IMMEDIATE`。主库编号、镜像编号/独立 revision、持久映射登记在**同一个 COMMIT** 中提交；没有“两次分别提交”的路径。索引、预算、来源文件和图片以只读文件摘要保护。

程序在连接前拒绝 `-wal/-shm/-journal` 和 WAL 文件头，不删除日志、不 checkpoint、不自动恢复。实际事务生成的镜像 rollback journal 属于本次 SQLite 事务，不能误列为其他保护文件。Windows 持有字节锁时不读取其锁定字节，但始终持有并校验同一锁文件。

故障测试覆盖临时号后、业务更新后、镜像更新后、COMMIT 前、进程直接退出、提交后回执磁盘错误及逆向恢复失败。异常回滚检查两库逐字节与原始合成输入相同；崩溃后工具拒绝日志。SQLite 自身恢复行为只在明确的合成故障测试中验证，不在历史/生产数据上自动执行。

## AI 旧结果与后续同步

独立 catalog_revision 由换号登记生成，不伪造原始同步指纹或 manifests。版本 GET 接口只读、带鉴权和 no-store，不调用索引状态服务或预算初始化。

生产查询把目录上下文与候选 ID 一起保存；反馈在已有调用锁内验证上下文，旧 list 形式或 revision 不符的查询拒绝。前端在还原页面、focus/pageshow/可见性变化、打开详情、确认与复制前核验版本；变化或无法核验时清除旧结果与手动复制回退。没有改颜色、布局或样式。

普通镜像同步仍使用原 publish 流程，保存新的真实同步指纹并保留换号 revision；测试覆盖零 manifests 的换号后再 publish。没有要求补录镜像之外的商品，没有重建向量、改变费用账本或调用付费服务。
