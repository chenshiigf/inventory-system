# 商品编号 V2.0 Phase 1：本地开发与隔离验收

本阶段不对现有数据库执行结构迁移或历史换号，不修改生产、图片、AI 数据及部署开关。

## 发号与兼容

- 新表 `product_code_months(period_ym, next_sequence)` 保存完整年月（例如 `202610`）和下一流水号。
- API 和 Excel 正式导入都经过 `create_product_record()`，在调用方的 `BEGIN IMMEDIATE` 事务内生成 `YYMM + 至少两位流水号`，包括未分类商品。
- 发号与 `created_at` 使用同一次含时区的服务器时间；月份按 UTC+8 计算，时间字段仍按 UTC 存储。保存时取月，不按上传、Preview 或打开表单时间取月。事务失败时商品、包装和计数器一起回滚。
- 初始化及后续分配均检查所有同前缀数字编号（含停用商品），保留计数器上界，避免与已有历史数据撞号。编号容量受 SQLite 整数范围约束；两位年份限定 2000–2099，拒绝跨世纪静默重用。
- 正式导入多行包装只占一个商品号；Preview 不占号。分类、仓库、包装、启停和出入库不重新发号。原货号字段保持独立。
- 排序依次为旧三段式、历史六位 `25xxxx`、月份编号、其他/空值。同类编号按各数字段比较；月份先比较 `YYMM`，再比较去除前导零后的流水长度和文本，避免七位编号错序与长整数溢出。
- 混合旧数据可继续查询、搜索、编辑和新增，不强制换号。新增前须对明确指定的数据库应用结构迁移；未初始化时返回清楚的 409，不自动迁移。
- `python -m app.backfill_product_codes` 永久停止执行旧回填，不打开默认数据库。旧函数仅保留给旧结构兼容验证，发现月份表时拒绝运行。

## 结构迁移

新 revision `d1e2f3a4b5c6` 接在 `c8d9e0f1a2b3` 后，只创建月份表与约束，不更新任何商品、包装、流水或分类计数器。首次分配按实际已有编号初始化上界。

空月份表允许隔离数据库 downgrade；存在任何计数记录时拒绝删除，防止重新升级后丢失已发行编号上界。未来恢复须保留计数器。普通代码回退不能替代数据库恢复评估。

## 合成历史换号预演

工具 `api/scripts/rehearse_product_codes.py` 只接受自己在操作系统临时目录新建的合成数据库。没有业务数据库默认值，不复制真实数据或图片，不接受工作区数据库、链接、硬链接或缺少内外身份标记的文件。

先在 PowerShell 创建一个尚不存在的目录名并生成合成数据：

```powershell
$fixtureDir = Join-Path $env:TEMP ('numbering-rehearsal-' + [guid]::NewGuid().ToString('N'))
api/.venv/Scripts/python.exe api/scripts/rehearse_product_codes.py create-fixture --directory $fixtureDir
$fixtureDb = Join-Path $fixtureDir 'fixture.sqlite3'
api/.venv/Scripts/python.exe api/scripts/rehearse_product_codes.py plan --database $fixtureDb
```

`plan` 默认只读，返回旧新号映射、冲突、商品/包装/流水数量、库存箱数及 `plan_sha256`。默认历史截止 ID 12，保留 ID 100 的模拟新商品；可显式修改截止 ID。历史选择按 ID 升序排名，包含停用、未分类和缺号商品。

实际改变合成数据库还需 `--execute --confirm-isolated-rehearsal --expected-plan-sha256 <本次摘要>` 三项。工具在写入前独占创建并 fsync 对照 CSV；数据已变则拒绝执行。目标号被选择范围外商品占用则拒绝，不自动改动范围外商品。范围内交换号采用事务内临时唯一号后统一赋值，全程保留唯一索引。

执行前保留原数字号及目标数字号对应月份的计数器上界；执行后比较所有非编号业务数据摘要、外键与 integrity_check，再提交。失败整批回滚，对照 CSV 保留；同一数据库禁止重复成功执行。若失败后的同一摘要需要再次预演，应新建合成 fixture，工具不会覆盖已有 CSV。

`create-fixture --conflict` 可生成范围外占号的拒绝场景。本工具故意不提供把真实数据库标记为可执行的入口，不能用于正式换号。
